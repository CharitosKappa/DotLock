# T5 vector implementation plan

SPEC §12 requires deterministic fixtures, a generator, and byte-identity checks.
No fixtures existed at start. All fixture inputs are public synthetic constants;
the generator must never accept user keys, credentials, files or phrases as input.

User-approved split (see SPEC_QUESTIONS Q3–Q5):

- T5a: fixed Argon2id, every §4 HKDF label, small AEAD, raw STREAM, credential
  encoding and BIP-39 mapping for implemented core APIs.
- T5b: slot/object/index/auth vectors after format/protocol decisions and their
  implementations. Do not claim raw AEAD/STREAM fixtures are object/slot fixtures.

Implementation steps for independent primitive coverage:

1. Test fixture presence/content and generator check failure before implementation.
2. Add narrowly gated deterministic-nonce fixture hooks inside dotlock-crypto;
   production APIs continue to obtain nonces from the OS.
3. Build a fixed-input generator in test-vectors with stable JSON bytes, a
   non-writing check mode and overwrite refusal. Never rewrite frozen fixtures.
4. Pin fixture bytes in tests; CI regenerates/checks without changing files.
5. Run required gates and source review; commit a separate draft PR.

Do not implement unresolved slot/object/auth behavior. Keep parent T5 incomplete
until all coverage exists. After T5a, resolve the relevant spec questions before
T6; add format vectors alongside T6–T9 and auth vectors alongside T24. Deferred
coverage alone does not block its prerequisite implementation or the M1 UI gate.
